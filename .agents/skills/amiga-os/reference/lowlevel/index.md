# lowlevel.library

The CD32-era "game library" (V40, OS 3.1). It reads the joy ports (joystick, mouse, CD32 game
controller) with one call, polls the keyboard, attaches simple keyboard / vertical-blank / CIA-timer
interrupt routines, measures elapsed time from the E-clock, and switches off system features a
full-screen game does not want (task switching, requesters, CD-eject reboot). Nearly every call
ignores Intuition's input focus: what you read is the raw hardware state.

## Opening

- Name `"lowlevel.library"` (no name macro in the include), base variable **`LowLevelBase`**
  (`struct Library *`; the SFD and Bartman's `<proto/lowlevel.h>` use this name).
- Open with version **40**. [SetJoyPortAttrsA](joyport.md#setjoyportattrsa) needs 40.27: check
  `lib_Version > 40 || (lib_Version == 40 && lib_Revision >= 27)` before calling it.
- On computers the library is loaded from `LIBS:`, so OpenLibrary can fail on a minimal boot disk;
  the CD32 has it in ROM (unverified).
- C: `#include <proto/lowlevel.h>` and `<libraries/lowlevel.h>`. asm: `include "libraries/lowlevel.i"`
  and `include "lvo/lowlevel_lib.i"`.

```c
#include <proto/exec.h>
#include <proto/lowlevel.h>
#include <libraries/lowlevel.h>

struct Library *LowLevelBase;

int main(void)
{
    LowLevelBase = OpenLibrary((CONST_STRPTR)"lowlevel.library", 40);
    if (LowLevelBase == NULL)
        return 20;                      /* needs OS 3.1 lowlevel.library */
    /* ... ReadJoyPort, GetKey, ... */
    CloseLibrary(LowLevelBase);
    return 0;
}
```

## Calling convention

- A6 = `LowLevelBase`, `jsr _LVOname(a6)`. Arguments in the registers on each entry's
  `Registers:` line, result in D0; D0, D1, A0, A1 are scratch.
- Odd registers: the Add*Int calls take the routine in A0 and its data in A1; Rem*Int,
  StartTimerInt and StopTimerInt take the handle in **A1**; SystemControlA and SetJoyPortAttrsA take
  the tag list in **A1** (not A0).
- [GetLanguageSelection](system.md#getlanguageselection) returns a UBYTE: test the low byte only.
- Usable from interrupts (per the autodocs): GetKey, QueryKeys (keep the array small), and
  ReadJoyPort once a first call from a task has returned something other than `JP_TYPE_NOTAVAIL`.
- LVOs -42, -120 and -126 are reserved slots (no function).

## Interrupt routines (AddKBInt, AddTimerInt, AddVBlankInt)

The routine you pass is called from interrupt code with a simpler contract than an exec server:

| Register | On entry | On exit |
|---|---|---|
| A1 | your `intData` | scratch |
| A5 | address of the routine itself | scratch |
| D0 | AddKBInt only: the rawkey code | **must be 0** |
| D1, A0, A6 | -- | scratch |
| D2-D7, A2-A4, A7 | -- | must be preserved |

- End with `moveq #0,d0` / `rts`. You pass a plain code address: no `struct Interrupt`, name or
  priority is involved.
- Interrupt rules apply: no Wait, AllocMem, DOS or anything that blocks; Signal and Cause are fine.
- Keep the routine and its data in memory until the matching Rem*Int call has returned.
- Only one keyboard routine and one vertical-blank routine can be installed system-wide, and
  AddTimerInt holds a single CIA timer until RemTimerInt: always check the returned handle.
- Always remove what you added before exiting (the Rem calls accept NULL).

## Version landmarks

| Version | Change |
|---|---|
| V40 (OS 3.1, CD32) | every function in this directory except SetJoyPortAttrsA |
| V40.27 | SetJoyPortAttrsA / SetJoyPortAttrs (`SJA_Type`, `SJA_Reinitialize`) |
| V45/V46 | third-party update described in the NDK 3.9 release notes (analog sticks, PSX/Sega pads, PPC calls); those functions are not in the NDK 3.9 includes or SFD: don't call them |
