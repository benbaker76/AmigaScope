# diskfont.library

diskfont.library loads bitmap (and, through bullet.library, outline) fonts from the `FONTS:` assign,
lists available fonts, scales fonts to sizes that do not exist on disk, and builds `.font` contents
files. Rendering with a font is graphics.library's job (SetFont, Text, CloseFont). diskfont only
gets the `struct TextFont` into memory.

## Fonts: ROM, memory and disk

- A font is requested with a `struct TextAttr` (graphics/text.h): `ta_Name` (e.g. `"topaz.font"`,
  including the `.font` suffix), `ta_YSize` (pixel height), `ta_Style` (`FSF_UNDERLINED` $01,
  `FSF_BOLD` $02, `FSF_ITALIC` $04, `FSF_EXTENDED` $08, `FSF_COLORFONT` $40, `FSF_TAGGED` $80) and
  `ta_Flags` (`FPF_ROMFONT` $01, `FPF_DISKFONT` $02, `FPF_REVPATH` $04, `FPF_TALLDOT` $08,
  `FPF_WIDEDOT` $10, `FPF_PROPORTIONAL` $20, `FPF_DESIGNED` $40, `FPF_REMOVED` $80). `struct TTextAttr`
  adds a tag list for DPI/dot-size.
- **graphics.library OpenFont** searches only fonts already in memory: the ROM fonts (topaz 8 and
  topaz 9) and fonts someone has loaded. If the name matches but the size does not, it returns the
  nearest match.
- **[OpenDiskFont](diskfont.md#opendiskfont)** first uses an in-memory copy and otherwise loads the font
  from `FONTS:<name>` (the `.font` contents file plus the `<name>/<size>` font file). V36+ can also scale
  a designed size.
- Both return a `struct TextFont *` for graphics SetFont(), and both are released with graphics
  **CloseFont()**. Every successful open needs exactly one CloseFont().
- V39+ OpenFont(): after OpenDiskFont() has loaded a font, pass OpenFont() the same TextAttr/TTextAttr
  you gave OpenDiskFont() (the match now includes DPI and dot size).
- Intuition never loads disk fonts for you. A `SA_Font`/`NewScreen.Font` TextAttr must name a font
  already in memory: open it with OpenDiskFont() first and keep it open while the screen uses it.

## Opening the library

- Name `"diskfont.library"`, base variable **`DiskfontBase`** (`struct Library *`). It is not in
  the Kickstart ROM: it is loaded from `LIBS:`, so OpenLibrary() can fail on a minimal boot disk.
- Version 36 for font scaling and TTextAttr, 45 (AmigaOS 3.9) for GetDiskFontCtrl/SetDiskFontCtrlA.

```c
#include <proto/exec.h>
#include <proto/diskfont.h>
#include <proto/graphics.h>
#include <diskfont/diskfont.h>

struct Library *DiskfontBase;

DiskfontBase = OpenLibrary((CONST_STRPTR)"diskfont.library", 36);
if (DiskfontBase) {
    /* ... OpenDiskFont / AvailFonts ... */
    CloseLibrary(DiskfontBase);
}
```

## Calling convention

- A6 = DiskfontBase, `jsr _LVOname(a6)` with `include "lvo/diskfont_lib.i"`. Arguments in the
  registers of each entry's `Registers:` line, result in D0. D0, D1, A0, A1 are scratch; other
  registers are preserved.
- Quirk: [DisposeFontContents](diskfont.md#disposefontcontents) takes its argument in **A1**.
- Loading means dos.library I/O: call OpenDiskFont, AvailFonts and NewFontContents from a
  **process**, never from a plain exec task or an interrupt.
- C prototype quirks: AvailFonts' buffer is typed `STRPTR` (it is really a `struct AvailFontsHeader *`),
  and NewScaledDiskFont returns the undefined `struct DiskFont *` (really a `struct DiskFontHeader *`).
  Cast in both cases.

## Version landmarks

| Version | Release | Change |
|---|---|---|
| V34 | 1.3 | NewFontContents, DisposeFontContents |
| V36 | 2.0 | NewScaledDiskFont; OpenDiskFont scales missing sizes unless `FPF_DESIGNED` is set; TTextAttr |

| V38 | 2.1 | outline font engine moved to bullet.library |
| V45 | 3.9 | GetDiskFontCtrl, SetDiskFontCtrlA (DPI defaults, AvailFonts cache and sort order) |
