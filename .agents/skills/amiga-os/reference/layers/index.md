# layers.library

layers.library splits one shared BitMap into overlapping rectangular layers, each with its own
RastPort, and keeps rendering in each layer clipped to its visible parts. It is the machinery
under every Intuition window: a Screen embeds a `struct Layer_Info`, each Window owns a
`struct Layer` (`Window->WLayer`, whose `rp` is `Window->RPort`). Programs that use Intuition
windows normally only touch layers for clip regions, backfill hooks and locking; creating and
moving layers yourself is for custom displays without Intuition. Background:
[concepts.md](concepts.md).

## Opening

- Name `"layers.library"` (no name macro in the includes); base variable **`LayersBase`**
  (`struct Library *` in Bartman's `<proto/layers.h>`). It is in the Kickstart ROM; graphics and
  Intuition use it themselves.
- Version: any ROM has the classic calls; open **36** for the hook layer calls and MoveSizeLayer,
  **39** for InstallLayerInfoHook, DoHookClipRects, SortLayerCR and `LAYERS_NOBACKFILL`.
- C: `#include <proto/layers.h>` with `<graphics/layers.h>` (Layer_Info, `LAYER*` flags) and
  `<graphics/clip.h>` (Layer, ClipRect). asm: `include "graphics/layers.i"`,
  `include "graphics/clip.i"`, `include "lvo/layers_lib.i"`.

```c
#include <proto/exec.h>
#include <proto/layers.h>

struct Library *LayersBase;

LayersBase = OpenLibrary((CONST_STRPTR)"layers.library", 39);
if (LayersBase == NULL)
    return 20;
/* ... */
CloseLibrary(LayersBase);
```

## Calling convention

- A6 = `LayersBase`, `jsr _LVOname(a6)`; arguments in the registers on each entry's `Registers:`
  line, result in D0. D0, D1, A0, A1 are scratch; D2-D7/A2-A6 are preserved.
- **dummy argument:** the original calls UpfrontLayer, BehindLayer, MoveLayer, SizeLayer,
  ScrollLayer, DeleteLayer and LockLayer take an unused `dummy` in A0 and the layer in **A1**. Pass 0
  (C: `DeleteLayer(0, layer)`). Later calls (UnlockLayer, BeginUpdate, EndUpdate,
  MoveLayerInFrontOf, MoveSizeLayer, InstallClipRegion, InstallLayerHook) take the layer in **A0**.
- The create calls use D0-D4 for the rectangle and flags, A2 for the SuperBitMap and (hook
  variants) A3 for the hook.
- graphics.library LockLayerRom / UnlockLayerRom take the same lock as
  [LockLayer](locking.md#locklayer) / [UnlockLayer](locking.md#unlocklayer), with the layer in A5;
  AttemptLockLayerRom is the non-blocking variant (no layers.library equivalent).
- Layer operations lock the Layer_Info and the affected layers and may block: never call them
  from interrupts, and never while holding locks in the wrong order (see [locking.md](locking.md)).

## Version landmarks

| Version | Release | Change |
|---|---|---|
| V36 | 2.0 | CreateUpfrontHookLayer, CreateBehindHookLayer, InstallLayerHook, MoveSizeLayer; `LAYERS_BACKFILL` (default hook) |
| V39 | 3.0 | InstallLayerInfoHook, DoHookClipRects, SortLayerCR; `LAYERS_NOBACKFILL` accepted by the hook calls; InstallLayerHook can return `LAYERS_NOBACKFILL` |

The classic functions carry no version in the NDK 3.9 autodocs. InitLayers, FattenLayerInfo and
ThinLayerInfo are obsolete (use NewLayerInfo/DisposeLayerInfo). The NDK 3.9 SFD lists nothing
newer than V39.
