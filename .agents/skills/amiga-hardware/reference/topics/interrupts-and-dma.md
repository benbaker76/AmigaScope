# Interrupts, beam timing and DMA arbitration

Interrupt levels and servicing, beam timing, and how DMA channels share the chip bus.

Registers: [INTENA](../registers/interrupts.md#intena), [INTENAR](../registers/interrupts.md#intenar),
[INTREQ](../registers/interrupts.md#intreq), [INTREQR](../registers/interrupts.md#intreqr),
[DMACON](../registers/dma-beam.md#dmacon), [DMACONR](../registers/dma-beam.md#dmaconr),
[VPOSR](../registers/dma-beam.md#vposr), [VHPOSR](../registers/dma-beam.md#vhposr),
[ICR](../registers/cia.md#icr). NDK bits: `hardware/intbits.i`, `hardware/dmabits.i`.

## Interrupt sources and levels

Paula combines 14 request bits into 68000 autovector levels 1-6. Level 7 (NMI) is not
generated by the base machine.

| Bit | NDK name | Level | Source | Autovector (+VBR) |
|---|---|---|---|---|
| 0 | `INTB_TBE` | 1 | serial transmit buffer empty | `$64` |
| 1 | `INTB_DSKBLK` | 1 | disk DMA block finished | `$64` |
| 2 | `INTB_SOFTINT` | 1 | software interrupt | `$64` |
| 3 | `INTB_PORTS` | 2 | INT2 line: **CIA-A** and expansion | `$68` |
| 4 | `INTB_COPER` | 3 | copper (set by a copper MOVE) | `$6C` |
| 5 | `INTB_VERTB` | 3 | start of vertical blank (line 0) | `$6C` |
| 6 | `INTB_BLIT` | 3 | blitter finished | `$6C` |
| 7-10 | `INTB_AUD0`-`AUD3` | 4 | audio block latched/finished | `$70` |
| 11 | `INTB_RBF` | 5 | serial receive buffer full | `$74` |
| 12 | `INTB_DSKSYNC` | 5 | disk sync word matched | `$74` |
| 13 | `INTB_EXTER` | 6 | INT6 line: **CIA-B** and expansion | `$78` |
| 14 | `INTB_INTEN` | -- | master enable (INTENA only) | |
| 15 | `INTB_SETCLR` | -- | set/clear control | |

The vector addresses are relative to the VBR on 68010 and later CPUs. SetPatch (or a boot
utility) may move the VBR into fast RAM; always compute `VBR + $6C`. See
[system-takeover.md](system-takeover.md#find-the-vbr).

## INTENA, INTREQ and the set/clear bit

- **INTENA** (write) enables sources; **INTENAR** (read) returns the current mask. An
  interrupt reaches the CPU only if its INTREQ bit, its INTENA bit **and** INTENA bit 14
  (INTEN) are all set, and the CPU's interrupt mask (SR) is below the level.
- **INTREQ** (write) sets or clears request bits; **INTREQR** (read) shows pending requests,
  enabled or not -- polling INTREQR works with the interrupt disabled.
- Both writes use bit 15: `$8000 ! bits` sets, `bits` alone clears.

```asm
        move.w  #$7fff,intena(a6)                       ; disable everything (incl. INTEN)
        move.w  #$7fff,intreq(a6)                       ; clear all pending requests
        move.w  #INTF_SETCLR!INTF_INTEN!INTF_VERTB,intena(a6)   ; enable VERTB
        move.w  #INTF_SETCLR!INTF_SOFTINT,intreq(a6)    ; raise a software interrupt
```

Request bits are **not** cleared by taking the interrupt. If the handler does not clear its
bit, the CPU re-enters the handler as soon as it returns -- the program hangs while
higher-level interrupts (e.g. music at level 3 while level 2 hangs) keep running.

## Servicing rules

1. Save every register you use (`movem.l ...,-(sp)`); interrupt code runs in supervisor mode on
   the system stack.
2. Read `INTREQR` (and `INTENAR` if several handlers share the level) to find the source.
3. For CIA interrupts, read the CIA's ICR **before** clearing PORTS/EXTER: the ICR read clears
   the CIA flags and releases its IRQ line; otherwise the request is set again immediately.
4. Do the work -- keep it short; lower levels are masked while you run.
5. Acknowledge only the bits you handled by writing them to INTREQ (bit 15 = 0), right before
   `RTE`. Writing INTREQ **twice** is common practice so the request line has dropped before
   `RTE` on fast CPUs (unverified -- no HRM statement).
6. Return with `RTE`. The stack frame is 6 bytes on a 68000 and at least 8 bytes on 68010+:
   never build frames by hand or pop the frame yourself.

## Level-3 handler

Bare-metal VERTB + COPER handler; install it only with the machine taken over
([system-takeover.md](system-takeover.md)). `vbr` holds the vector base (0 on a 68000).

```asm
        include "hardware/custom.i"
        include "hardware/intbits.i"

        section code,code
InstallLevel3:                          ; a6 = $dff000
        move.w  #INTF_VERTB!INTF_COPER,intena(a6)       ; off while patching
        move.l  vbr,a0
        move.l  $6c(a0),oldlevel3
        move.l  #Level3,$6c(a0)
        move.w  #INTF_VERTB!INTF_COPER,intreq(a6)       ; drop stale requests
        move.w  #INTF_SETCLR!INTF_INTEN!INTF_VERTB!INTF_COPER,intena(a6)
        rts

Level3:
        movem.l d0-d7/a0-a6,-(sp)
        lea     $dff000,a6
        move.w  intreqr(a6),d0
        and.w   intenar(a6),d0
        btst    #INTB_VERTB,d0
        beq.s   .novb
        addq.l  #1,framecount           ; per-frame work goes here
.novb   btst    #INTB_COPER,d0
        beq.s   .nocop
        addq.l  #1,copercount           ; raster work (the copper set COPER at a line)
.nocop  and.w   #INTF_VERTB!INTF_COPER!INTF_BLIT,d0
        move.w  d0,intreq(a6)           ; acknowledge what we saw
        move.w  d0,intreq(a6)
        movem.l (sp)+,d0-d7/a0-a6
        rte

        section vars,bss
vbr:        ds.l    1
oldlevel3:  ds.l    1
framecount: ds.l    1
copercount: ds.l    1
```

To chain to the previous handler instead of returning (rarely wanted when the OS is dead),
restore the registers and `move.l oldlevel3,-(sp)` + `rts`.

With the OS alive, do not touch the vectors: add a server with `AddIntServer(INTB_VERTB, is)`
(see [system-takeover.md](system-takeover.md#os-friendly-alternative-addintserver)).

## CIA interrupts

- CIA-A drives INT2 -> PORTS (level 2); CIA-B drives INT6 -> EXTER (level 6).
- A CIA's ICR read returns the pending flags (bit 7 = IR: any enabled source fired) and
  **clears all of them**. Handle every source you care about from that single read.
- Enable CIA sources with a write to ICR: bit 7 = 1 sets the mask bits you pass, bit 7 = 0
  clears them (e.g. `move.b #CIAICRF_SETCLR!CIAICRF_SP,ciaicr(a0)`). The mask cannot be read
  back.
- With the OS alive use `cia.resource` (AddICRVector/AbleICR) -- the OS uses CIA timers and the
  keyboard. Details and a keyboard handler: [cia-and-io.md](cia-and-io.md#keyboard).

## Frame and beam timing

| | PAL | NTSC |
|---|---|---|
| Lines per field | 312 / 313 alternating in interlace | 262 / 263 alternating in interlace |
| Colour clocks per line | 227 | 227 and 228 alternating (long line, VPOSR LOL) |
| Line duration | about 64 us | about 63.5 us |
| One colour clock | 281.94 ns | 279.37 ns |
| Vertical blank (nothing displayed) | lines 0-28 | lines 0-20 |
| VERTB interrupt | line 0 | line 0 |
| Standard display lines | `$2C`-`$12B` | `$2C`-`$F3` |

- Non-interlaced displays repeat one field type every frame (unverified: LOF stays set, i.e. the
  long field; do not rely on it).
- In interlace, VPOSR bit 15 (LOF) = 1 during the long field. Select the long/short copper list
  on it ([copper.md](copper.md#interlace)).
- The HRM also gives a minimum vertical blank of 20 (NTSC) / 25 (PAL) lines for VERTB work;
  the playfield chapter's display tables use 21/29. Treat line `$2C` as the first safe display
  line.

## Reading the beam position

VPOSR (`$DFF004`) and VHPOSR (`$DFF006`) read as one long: bit 16 = V8, bits 15-8 = V7-V0,
bits 7-0 = horizontal position in colour clocks (`$00`-`$E2`). VPOSR bit 15 = LOF; bits 14-8
hold the Agnus ID on ECS ([ecs.md](ecs.md)).

```asm
; wait until the beam reaches line d1 (0-311), a6 = $dff000
WaitLine:
.l      move.l  vposr(a6),d0
        lsr.l   #8,d0
        and.w   #$01ff,d0
        cmp.w   d1,d0
        bne.s   .l
        rts

; wait for the next vertical blank by polling (VERTB may be disabled in INTENA)
WaitVBL:
        move.w  #INTF_VERTB,intreq(a6)
.w      move.w  intreqr(a6),d0
        btst    #INTB_VERTB,d0
        beq.s   .w
        move.w  #INTF_VERTB,intreq(a6)
        rts
```

- Exact equality can miss a line if an interrupt delays the loop by more than one line; then
  it waits a whole frame. Use ">=" logic when that matters (mind the wrap at line 0).
- A byte read of `vhposr(a6)` gives V7-V0 only -- enough for "has the line changed" delays.
- With the light pen enabled (BPLCON0 bit 3) the counters latch at the pen position; keep LPEN 0.
- VPOSW/VHPOSW exist for chip testing; never write them.

## DMA bus arbitration

All custom-chip DMA and all CPU access to chip RAM (and chip-arbitrated space: custom
registers, slow RAM) share one bus. Agnus divides each scan line (227.5 colour clocks, about
226 usable cycles) into slots:

| Per line | Cycles |
|---|---|
| memory refresh | 4 |
| disk DMA | 3 |
| audio DMA (one word per channel) | 4 |
| sprite DMA (2 words per channel) | 16 |
| bitplane DMA | up to 80 for a standard display (more for wide/hires) |

Priority, highest first:

1. Fixed-slot channels: disk, audio, bitplanes, sprites (bitplanes can take sprite slots when
   DDFSTRT is early -- [sprites.md](sprites.md#sprite-dma-and-ddfstrt)).
2. Copper -- requests only odd cycles, so it never collides with the fixed slots.
3. Blitter.
4. CPU.

Consequences:

- The CPU normally gets alternate cycles and runs at full speed. **More than 4 lores planes**
  steal half of the CPU's chip-memory cycles during the display; **4 hires planes** take them
  all, so chip-RAM code, copper and blitter only progress in the blanking areas.
- The blitter takes every cycle the copper and fixed channels leave. DMACON bit 10
  (`DMAF_BLITHOG`, "blitter nasty") = 1 lets it keep them all; 0 makes it give the CPU one cycle
  after the CPU has waited three.
- Code and data in **fast RAM or ROM are never slowed** by DMA -- put heavy CPU work there.
- A blit that overruns vertical blank competes with the display fetch and slows down on
  display lines. The amigascope-workflow skill's `dma_profile.py` records the owner of every
  colour clock per line (`parse` summary, `blits` per-blit raster spans, `map` PNG).
- Never use `TAS` (its read-modify-write cycle cannot be split around DMA).

## Common mistakes

- Installing a handler at `$6C` on a machine whose VBR is not 0.
- Forgetting to acknowledge INTREQ, or acknowledging with bit 15 set (`$8020` sets VERTB again).
- Clearing PORTS/EXTER before reading the CIA ICR (instant re-trigger), or reading ICR twice and
  losing flags from the first read.
- Enabling a source in INTENA without INTEN (bit 14) after a `$7FFF` write.
- Using `clr.w intreq(a6)` (reads a write-only register on the 68000 first).
- Long work in a level-3 handler: the next VERTB is lost and level 1-2 interrupts (keyboard,
  serial) starve.
- Calling OS functions from an interrupt handler while the OS is disabled, or `Wait`-ing ones
  at any time from interrupt code.
- Measuring time with busy loops instead of the beam counter or a CIA timer.
