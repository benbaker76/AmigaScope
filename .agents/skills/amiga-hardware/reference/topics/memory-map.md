# Amiga memory map

Where chip RAM, CIAs, custom chips, slow RAM, AUTOCONFIG space and ROM are mapped.

Hardware addresses below are fixed. **Everything the OS allocates is not**: library bases,
the system copper list, task structures move from boot to boot. The only fixed pointer is
`$000004` = ExecBase. Ask the OS (or `FindConfigDev`, `AvailMem`, `TypeOfMem`) instead of
probing.

## 24-bit map (A500, A1000, A2000; A3000 low 16 MB)

| Range | Contents | Notes |
|---|---|---|
| `$000000`-`$0003FF` | 68k exception vector table (when VBR = 0) | see [Low memory](#low-memory-and-exception-vectors) |
| `$000000`-`$07FFFF` | Chip RAM, first 512K (A1000: 256K + 256K option) | reachable by all DMA |
| `$080000`-`$0FFFFF` | Chip RAM to 1 MB (Fat Agnus 8372A, A2000 jumpered) | |
| `$100000`-`$1FFFFF` | Chip RAM to 2 MB (A3000 ECS; AGA machines) | reserved on 1 MB machines |
| `$200000`-`$9FFFFF` | Zorro II memory space, 8 MB: AUTOCONFIG fast RAM | |
| `$A00000`-`$B7FFFF` | Reserved; A3000: Zorro II I/O expansion space | |
| `$B80000`-`$BEFFFF` | Reserved | |
| `$BFD000`-`$BFDF00` | **CIA-B** (8520), even byte addresses `$BFDr00` | IRQ -> INT6 (level 6) |
| `$BFE001`-`$BFEF01` | **CIA-A** (8520), odd byte addresses `$BFEr01` | IRQ -> INT2 (level 2) |
| `$C00000`-`$D7FFFF` | Internal "slow" / pseudo-fast RAM (A500 trapdoor, A2000) | A3000 map: `$C00000`-`$C7FFFF` expansion memory |
| `$D80000`-`$DBFFFF` | Reserved | |
| `$DC0000`-`$DCFFFF` | Real-time clock (not on all models) | use battclock.resource |
| `$DD0000`-`$DDFFFF` | Reserved; A3000: SCSI controller | |
| `$DE0000`-`$DEFFFF` | Reserved; A3000: motherboard resources | |
| `$DFF000`-`$DFFFFF` | **Custom chip registers** (registers occupy `$DFF000`-`$DFF1FF`) | word access |
| `$E00000`-`$E7FFFF` | Reserved | |
| `$E80000`-`$E8FFFF` | AUTOCONFIG space: unconfigured Zorro II boards appear here | [zorro-autoconfig.md](zorro-autoconfig.md) |
| `$E90000`-`$EFFFFF` | Secondary AUTOCONFIG space (usually 64K I/O boards) | Zorro II I/O |
| `$F00000`-`$F7FFFF` | Reserved; A3000: diagnostic ROM | |
| `$F80000`-`$FFFFFF` | 512K system ROM (Kickstart 2.0 and later) | |
| `$FC0000`-`$FFFFFF` | 256K system ROM (Kickstart 1.3 and earlier) | |

At reset a ROM image is also mapped at `$000000` (overlay) so the CPU can fetch its reset
vectors; writing the CIA-A `OVL` bit (PRA bit 0) switches the overlay off and brings chip RAM back (the boot ROM does this). Never set that
bit while chip RAM is in use.

## A3000 32-bit space

| Range | Contents |
|---|---|
| `$00000000`-`$00FFFFFF` | the 24-bit map above |
| `$01000000`-`$03FFFFFF` | Reserved |
| `$04000000`-`$07FFFFFF` | Motherboard fast RAM |
| `$08000000`-`$0FFFFFFF` | Coprocessor (CPU) slot expansion |
| `$10000000`-`$7FFFFFFF` | Zorro III expansion space |
| `$80000000`-`$FEFFFFFF` | Reserved |
| `$FF000000`-`$FF00FFFF` | Zorro III configuration area |
| `$FF010000`-`$FFFFFFFF` | Reserved |

The NDK (`libraries/configregs.i`) defines the Zorro III board area as
`EZ3_CONFIGAREA $40000000`-`EZ3_CONFIGAREAEND $7FFFFFFF`; boards get addresses there.

## Low memory and exception vectors

With VBR = 0 (68000, or 68010+ before SetPatch moves it) the vector table starts at `$0`.
On a 68010+ **add the VBR** to every vector address; see
[system-takeover.md](system-takeover.md#find-the-vbr).

| Address | Vector |
|---|---|
| `$000` / `$004` | reset SSP / PC at power-on (from the ROM overlay); in RAM `$004` holds **ExecBase** |
| `$008`-`$02C` | bus error, address error, illegal instruction, divide by zero, CHK, TRAPV, privilege violation, trace, line-A, line-F (standard 68k assignment, unverified against a local source) |
| `$064` | level 1 autovector: TBE, DSKBLK, SOFTINT |
| `$068` | level 2: PORTS (CIA-A, INT2) |
| `$06C` | level 3: COPER, VERTB, BLIT |
| `$070` | level 4: AUD0-AUD3 |
| `$074` | level 5: RBF, DSKSYNC |
| `$078` | level 6: EXTER (CIA-B, INT6) |
| `$07C` | level 7: NMI (not generated by the base machine) |
| `$080`-`$0BC` | TRAP #0 - #15 |
| `$0C0`-`$0FF` | further processor vectors (FPU/MMU on 68020+) |
| `$100`-`$3FF` | "user" vectors: reserved by Motorola, unused on the Amiga |

Level assignments come from the INTENA bit table (HRM Appendix A); the autovector addresses
are the standard 68000 layout ($64 + 4*(level-1)).

## CIA register layout

Each 8520 has 16 byte registers. The register number `r` is the third hex digit of the
address. NDK offsets (`hardware/cia.i`) are relative to `$BFE001` / `$BFD000`.

| r | CIA-A address | CIA-B address | NDK offset | Register |
|---|---|---|---|---|
| 0 | `$BFE001` | `$BFD000` | `ciapra` | PRA -- port A data |
| 1 | `$BFE101` | `$BFD100` | `ciaprb` | PRB -- port B data |
| 2 | `$BFE201` | `$BFD200` | `ciaddra` | DDRA (1 = output) |
| 3 | `$BFE301` | `$BFD300` | `ciaddrb` | DDRB |
| 4/5 | `$BFE401`/`$BFE501` | `$BFD400`/`$BFD500` | `ciatalo`/`ciatahi` | timer A |
| 6/7 | `$BFE601`/`$BFE701` | `$BFD600`/`$BFD700` | `ciatblo`/`ciatbhi` | timer B |
| 8-A | `$BFE801`-`$BFEA01` | `$BFD800`-`$BFDA00` | `ciatodlow`/`mid`/`hi` | TOD counter |
| C | `$BFEC01` | `$BFDC00` | `ciasdr` | serial data (CIA-A: keyboard) |
| D | `$BFED01` | `$BFDD00` | `ciaicr` | interrupt control |
| E | `$BFEE01` | `$BFDE00` | `ciacra` | control A |
| F | `$BFEF01` | `$BFDF00` | `ciacrb` | control B |

Port bit assignments are in [cia-and-io.md](cia-and-io.md#port-bit-assignments).

## Custom chip register block

Registers are word-sized, `$DFF000`-`$DFF1FE` (OCS/ECS use up to `$DFF1E4`; AGA adds
`$DFF1FC` FMODE). Rough grouping by offset:

| Offsets | Group | Guide |
|---|---|---|
| `$000`-`$01E` | read-only status: DMACONR, VPOSR, VHPOSR, JOYxDAT, CLXDAT, ADKCONR, POTxDAT, POTGOR, SERDATR, DSKBYTR, INTENAR, INTREQR | various |
| `$020`-`$03E` | disk pointer/length, REFPTR, VPOSW/VHPOSW, COPCON, SERDAT/SERPER, POTGO, JOYTEST, strobes | [cia-and-io.md](cia-and-io.md) |
| `$040`-`$074` | blitter | [blitter.md](blitter.md) |
| `$07C`-`$09E` | DENISEID, DSKSYNC, copper locations/strobes, DIW/DDF, DMACON, CLXCON, INTENA, INTREQ, ADKCON | [copper.md](copper.md), [playfields.md](playfields.md) |
| `$0A0`-`$0DA` | audio channels 0-3 (`$10` apart) | [audio.md](audio.md) |
| `$0E0`-`$0F6` | bitplane pointers 1-6 | [playfields.md](playfields.md) |
| `$100`-`$11E` | BPLCONx, modulos, BPLxDAT | [playfields.md](playfields.md) |
| `$120`-`$17E` | sprite pointers, SPRxPOS/CTL/DATA/DATB | [sprites.md](sprites.md) |
| `$180`-`$1BE` | COLOR00-COLOR31 | [playfields.md](playfields.md) |
| `$1C0`-`$1E4` | ECS beam/sync/blank programming, BEAMCON0, DIWHIGH | [ecs.md](ecs.md) |

## Common mistakes

- Probing for fast RAM by writing `$200000` and reading it back: on a 2 MB chip RAM machine
  without fast RAM the write mirrors onto `$000000` and destroys low memory. Use `AvailMem`/
  `TypeOfMem`, or check for the mirror by comparing against `$0`.
- Assuming chip RAM ends at `$080000` (or `$200000`) -- query the OS.
- Word or long access to CIA addresses, or CIA-A at even addresses: CIA-A answers only at odd
  addresses on the low data byte, CIA-B only at even addresses on the high byte.
- Reading vectors at `$6C`/`$80` on a 68010+ machine after SetPatch moved the VBR.
- Jumping into ROM at fixed addresses (breaks on every Kickstart revision).
- Writing CIA-A PRA as a whole byte: bit 0 is `OVL` (1 maps the ROM over chip RAM -- polarity unverified). Use
  `bset`/`bclr` on the bit you mean (usually `CIAB_LED`).
